# Spec: a box can be promoted to a declared machine from the panel

## Design

`p` on a box row builds the `services.boxes.machines.<name>` snippet for that
box, copies it with `wl-copy`, and shows it. Nothing is written to disk, no
engine process runs, and the mutation lock is untouched.

### The snippet, in `Model.js`

```js
function promoteSnippet(name, image) { … }   // string, or null
```

It returns exactly what nixarchy's `promote_box` prints
(`pkgs/box.nix:180-210`), so the two agree while both exist:

```nix
programs.nixarchy.services.boxes.machines.<name> = {
  image = "<image>";
  # Add whatever else this box needs -- additional_packages, init_hooks,
  # exported_apps -- see distrobox-assemble's manual. This snippet only
  # knows what podman recorded for the image; nothing else about how
  # '<name>' was set up by hand is knowable after the fact -- that is the
  # whole point of promoting it: from here on it is declared instead.
};
```

`null` unless `isBoxName(name)` and `isImageRef(image)` (both already exist,
`Model.js:674` for the latter). Those two are the only values interpolated, and
both are already constrained to characters that cannot close the Nix string or
the comment, so the snippet cannot be broken out of.

The image is the row's own `image` field, parsed from the engine's `ps` output
at `Model.js:239` and already carried through `ROW_FIELDS` (`Model.js:303`). No
`podman inspect` — approved question 1.

### Copying, in `Model.js` and `DistroboxState.qml`

`copyArgv(name)` (`Model.js:577`) grows a sibling:

```js
function copyTextArgv(text) { … }            // ["wl-copy", "--trim-newline", text] or null
```

`copyArgv` becomes `isBoxName(name) ? copyTextArgv(name) : null`, so there is
one place that knows the clipboard command. The snippet is a single argv
element; no shell is involved. `DistroboxState.copyName` (line 239) gains a
`copyText(text)` twin over the same `copyProcess`, and `copyName` delegates to
it.

### Showing it, in `DistroboxView.qml`

A new mode, `"snippet"`, drawn by a **second `LogView`** instance bound to a
local `snippetLines`, with `title: "promote <name>"`, `running: false` and
`exitCode: 0`. `LogView` is already generic over those four properties
(`LogView.qml:13-16`), and Esc already returns to the list.

A second instance rather than new bindings on the existing one, because the
existing `LogView` is bound to the stream (`DistroboxState.log`,
`streamTitle`, `streaming`, `streamExit`) and AGENTS.md requires that a create
or upgrade in flight is never disturbed. With two instances, `o` still returns
to the running job's log while a snippet is on screen, and promoting during a
create changes nothing about the stream.

`handleTextKey` gains `p` next to `y` (`DistroboxView.qml:238`); `dispatch`
gains a `"promote"` verb next to `"copy"` (line 141), before the
`allowsVerb`/lock check, because promote is read-only and must work while a
mutation holds the lock.

No row button. `copy` has none either (`rowActions`, `Model.js:591-599`), and a
glyph per row for a paste-into-your-flake action is not worth the width.

### Everything else

One `SHORTCUTS` row (`Model.js:31`): `{ group: "Box", keys: "p", text: "Copy a
Nix snippet that declares it in nixarchy" }`. `p` is unused today. A `Snippet`
group is not added; Esc and the scroll keys are already documented under `Log`
and behave identically.

`docs/usage.md` and `README.md` get the key and one line on what to do with the
snippet, in the same PR.

## Alternatives rejected

- **`podman inspect --type container --format '{{.Config.Image}}'` per promote,**
  as the CLI does. An extra process, an extra failure path, and a `Process`
  round trip for a value the row already holds. The two can differ only if the
  image was retagged or pulled by digest after create; the snippet is a draft
  the user edits anyway.
- **Writing or patching the user's flake.** Out of scope, and the CLI does not
  either. The panel has no idea where the flake is.
- **A toast-style status line instead of a view.** The snippet is eleven lines;
  a status line truncates it, and the user should see what landed on their
  clipboard.
- **Reusing the single existing `LogView` with conditional bindings.** Risks the
  in-flight stream for a handful of saved lines.
- **Hiding `p` for docker boxes.** The snippet is text the user chooses to
  paste, and `DBX_CONTAINER_MANAGER=docker` users may still be moving to
  podman. Approved question 4.
- **A row button.** See above.

## Risks

- **A wrong image in the snippet** if the box's image was retagged since
  creation. Mitigated by the comment block, which already says the snippet only
  knows what the engine recorded. Same class of staleness the CLI has between
  `inspect` calls.
- **`wl-copy` missing** (not a Wayland session, or Omarchy not providing it).
  Same failure as `y` today: the `Process` fails silently. No new exposure, and
  the snippet is still on screen to select by hand.
- **`p` colliding** with a future key. Checked: unused in `handleTextKey`
  (`DistroboxView.qml:225-240`).
- **The second `LogView`** adds an always-instantiated, usually-invisible item
  to both surfaces. Height collapses to 0 when hidden, as the first one does.
- **Hosts:** none beyond the plugin. p620 and razer pick it up on the next
  input bump; nothing in nixarchy changes until #801 is closed separately.

## Verification

- `node tests/run.js` — new rows in `tests/model/commands.test.js`:
  `promoteSnippet` for a normal box; `null` for a bad name; `null` for a bad
  image; hostile input (a name or image carrying `"`, `}`, `\n`, `$`) rejected
  rather than interpolated; `copyTextArgv` shape and its `null`; `copyArgv`
  unchanged for an existing name.
- `nix flake check` and `nix flake check --all-systems --no-build` — no new
  file, so the `files` list is unchanged; the no-hex-colour and no-`pacman`
  gates still pass.
- `nix build` + `omarchy plugin validate` on a fresh clone, per AGENTS.md.
- Live on a nixarchy desktop, both surfaces: `p` on a `t1` box shows the
  snippet, `wl-paste` returns it byte-for-byte equal to
  `nixarchy box promote t1`; Esc returns to the list; `p` during a streaming
  create leaves the stream intact and `o` still returns to it; `qs log` clean.
