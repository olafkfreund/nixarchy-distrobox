# Spec: a box can be promoted to a declared machine from the panel

## Design

### The snippet: nixarchy's, byte for byte

`nixarchy box promote <name>` prints this, read from the **built** script
(`nixarchy-box` on nixarchy `main`). The Nix `''…''` string strips its
indentation, so the source's layout isn't the output's:

```
programs.nixarchy.services.boxes.machines.<name> = {
  image = "<image>";
  # Add whatever else this box needs -- additional_packages, init_hooks,
  # exported_apps -- see distrobox-assemble's manual. This snippet only
  # knows what podman recorded for the image; nothing else about how
  # '<name>' was set up by hand is knowable after the fact -- that is the
  # whole point of promoting it: from here on it is declared instead.
};
```

The first line starts at column 0 and the body is indented two spaces. `<name>`
appears twice: in the attribute path and in the quoted comment. There's no
trailing text after `};`, so what's copied ends with that newline. The owner
decided "identical to the CLI", so nothing is added, even where the panel could
read more.

`Model.js` gains one pure function, `promoteSnippet(name, image)`, which returns
exactly that text. It's a constant template, so it can't drift, and a test
holds it against a fixture copied from the built CLI (see Verification).

### The image: the same source as the CLI

The CLI reads `podman inspect --type container --format '{{.Config.Image}}' <name>`.
The panel does the same, through the engine it already uses
(`Model.engineFor(settings.containerManager)`, `DistroboxState.qml:23`), never
a second podman on `PATH`. The intent's constraint and the CLI's header give
the reason.

- **A new argv builder,** `promoteImageArgv(engine, name)`, returns
  `[engine, "inspect", "--type", "container", "--format", "{{.Config.Image}}", name]`.
  It's the same shape as `inspectHomesArgv` (`Model.js:527`).
- **It runs once per keypress,** never on the poll. The row already shows an
  image from `ps`, but `ps` and `inspect` can write the name differently, and
  the snippet must say what the CLI says.
- **If the result is empty** (the engine is down, or the box is gone between
  list and keypress), the panel shows "can't read <name>'s image: <engine>
  inspect found nothing" and copies nothing. An empty `image = ""` is never
  produced (intent outcome).

### The key and the button

- **`p` on a selected row** runs promote. The owner decided on `p`.
  `Model.js`'s `SHORTCUTS` list (line 31) gains
  `{ group: "Box", keys: "p", text: "Promote to a declared machine (copies the snippet)" }`,
  and the shortcut sheet renders from that list, so the sheet updates itself.
- A row action button with the same effect, beside the existing ones in
  `BoxList.qml`, using an icon from the set the row already uses.
- **The result** shows the snippet in the panel's message area, in a
  monospaced, selectable block. It's copied by `wl-copy`, with the snippet
  passed as one argv element, the way `copyArgv` (`Model.js:575-578`) passes a
  name. `copyArgv` itself isn't reused: its `isBoxName` guard rejects text, and
  its `--trim-newline` would drop the final newline. A sibling,
  `promoteCopyArgv(name, image)`, returns `["wl-copy", promoteSnippet(name, image)]`,
  or `null` for an invalid name or an empty image. The block is followed by one
  line: "Copied. Paste into this host's nixarchy configuration; a rebuild then
  owns the box."

### What it never does

It writes no file: not the user's flake, not `~/.config/nixarchy/*`. It doesn't
run `nixarchy box`, and it has no nixarchy dependency. The snippet is just text,
and copying it is harmless on a machine without nixarchy (intent).

## Alternatives rejected

- **Calling `nixarchy box promote` from the panel.** That depends on a CLI
  nixarchy is retiring (nixarchy#801), and on its PATH resolution of podman,
  which is the hazard its own header describes.
- **Filling in more fields** (`init` from labels, packages). The owner decided
  "identical to the CLI".
- **Writing the snippet into `~/.config/nixarchy/services.nix`** through
  nixarchy's writer. The intent is read-only by design, and the user decides
  where declarations go.

## Risks

- **The CLI's comment text drifts before nixarchy#801 retires it.** The
  fixture test catches that only when someone refreshes the fixture. Once the
  CLI is retired, this panel *is* the source of truth, and nixarchy's manual
  should quote it. That goes on nixarchy#801.
- **A box whose name contains characters invalid in a Nix attribute path**
  (distrobox allows `.`). The CLI has the same limitation and emits it
  unquoted. Identical output means the same limitation, which the note in the
  message area names. Quoting it would be a divergence, which the owner ruled
  out.
- **Docker reports `.Config.Image` the same way podman does,** so the snippet
  is the same whichever engine is used.
