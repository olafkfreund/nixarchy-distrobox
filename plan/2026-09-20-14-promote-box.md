# Plan: a box can be promoted to a declared machine from the panel

## Approved decisions

`p` on a box row builds the `programs.nixarchy.services.boxes.machines.<name>`
snippet for that box, copies it with `wl-copy`, and shows it. Read-only: no
engine process, no file written, the mutation lock untouched, the create /
upgrade stream untouched.

- The snippet is byte-identical to what nixarchy's `promote_box` prints
  (`pkgs/box.nix:180-210`), comment block included, so the two agree while both
  exist.
- The image comes from the row's own `image`, parsed from the engine's `ps`
  output at `Model.js:239`. No `podman inspect`.
- `Model.promoteSnippet(name, image)` returns the text, or `null` unless
  `isBoxName(name)` and `isImageRef(image)` both pass. Those are the only two
  interpolations.
- `Model.copyTextArgv(text)` is the one place that knows the clipboard command;
  `copyArgv(name)` delegates to it.
- A new view mode `"snippet"` is drawn by a **second `LogView` instance**, not
  by rebinding the existing one, which belongs to the stream.
- No row button. `p` works while a mutation holds the lock, so its verb is
  handled before the `allowsVerb` check.
- Docker boxes get `p` too.

The exact snippet, with `<name>` and `<image>` substituted:

```nix
programs.nixarchy.services.boxes.machines.<name> = {
  image = "<image>";
  # Add whatever else this box needs -- additional_packages, init_hooks,
  # exported_apps -- see distrobox-assemble's manual. This snippet only
  # knows what podman recorded for the image; nothing else about how
  # '<name>' was set up by hand is knowable after the fact -- that is the
  # whole point of promoting it: from here on it is declared instead.
};
```

## Steps

One commit per step, each citing the step.

1. **`Model.js`: the snippet and the clipboard argv.** Add
   `promoteSnippet(name, image)` near the other command builders (below
   `copyArgv`, `Model.js:575`), returning the text above or `null`. Add
   `copyTextArgv(text)` returning `["wl-copy", "--trim-newline", text]`, or
   `null` for a non-string or empty text; rewrite `copyArgv(name)` as
   `isBoxName(name) ? copyTextArgv(name) : null`. Export both.
   → verify by `node tests/run.js` still green (step 2 adds the new rows).

2. **`tests/model/commands.test.js`: the rows.** `promoteSnippet` for a normal
   box, asserted against the literal expected string; `null` for a bad name;
   `null` for a bad image; hostile rows where the name or image carries `"`,
   `}`, `\n`, `$` or `${` and the result must be `null`, never an interpolation;
   `copyTextArgv` shape, and `null` for `""`, `null` and a non-string;
   `copyArgv("t1")` unchanged.
   → verify by `node tests/run.js` green with the new rows counted.

3. **`Model.js`: the shortcut row.** Add
   `{ group: "Box", keys: "p", text: "Copy a Nix snippet that declares it in nixarchy" }`
   to `SHORTCUTS` (line 31), after the `y` row.
   → verify by `node tests/run.js` green (`shortcutGroups` is covered), and `?`
   in the live check at step 7.

4. **`DistroboxState.qml`: `copyText`.** Add `copyText(text)` beside
   `copyName` (line 239) over the same `copyProcess`, and make `copyName`
   delegate: `copyText` guards on `argv && !copyProcess.running` exactly as
   `copyName` does today.
   → verify by reading the diff; exercised live at step 7.

5. **`DistroboxView.qml`: the mode, the key, the verb.** Add
   `property var snippetLines: []` and `property string snippetName: ""`; a
   `promote(name)` function that builds the snippet from the row, calls
   `DistroboxState.copyText`, fills `snippetLines` and `setMode("snippet")`,
   and does nothing when `promoteSnippet` returns `null`; `p` in
   `handleTextKey` next to `y` (line 238); `if (verb === "promote")` in
   `dispatch` next to `"copy"` (line 141), above the `allowsVerb` check. Extend
   `focusForMode` (line 88) and the `mode !== "list"` guards so `"snippet"`
   behaves like `"log"`. Add the second `LogView` after the existing one
   (line 355) with `visible: root.mode === "snippet"`, `lines: root.snippetLines`,
   `title: "promote " + root.snippetName`, `running: false`, `exitCode: 0`,
   `onBackRequested: root.setMode("list")`.
   → verify by `nix build`, then the live check at step 7.

6. **`docs/usage.md` and `README.md`.** The `p` key in the key table, and one
   line: it copies a snippet to paste into your nixarchy flake, it edits
   nothing, and the box keeps working either way.
   → verify by reading, and `nix flake check`.

7. **Live check on a nixarchy desktop**, per AGENTS.md "Verifying live". Both
   surfaces, with a `t1` box.
   → verify by the Tests section below.

## Tests

```bash
d=$(mktemp -d) && git clone -q . "$d/p" && rm -rf "$d/p/.git" && omarchy plugin validate "$d/p"
```

Live, after installing a copy and `omarchy-restart-shell`:

- `p` on `t1` in the menu shows the snippet; `wl-paste` equals
  `nixarchy box promote t1` byte for byte.
- The same in the bar popup.
- Esc returns to the list with the cursor still on `t1`.
- `p` while a create streams: the stream is unaffected, and `o` still returns
  to it.
- `?` lists `p` under Box.
- `qs log -i <instance>` clean.

Tear down with `distrobox rm t1`.

## Rollback

the current behaviour.
