# Plan: a box can be promoted to a declared machine from the panel

## Approved decisions (from the spec)

- **The snippet is nixarchy's, byte for byte.** `promoteSnippet(name, image)`
  in `Model.js` returns exactly what `nixarchy box promote <name>` prints:
  the attribute line at column 0, a two-space body, `<name>` twice (path and
  comment), ending `};` plus a newline. Nothing is added, even where the panel
  could read more.
- **The image comes from the same call the CLI makes,** through the engine the
  panel already uses: `<engine> inspect --type container --format
  '{{.Config.Image}}' <name>`, once per keypress, never on the poll. An empty
  result shows an error and copies nothing; `image = ""` is never produced.
- **`p` promotes the selected row**, plus a row button. The result is shown in
  a selectable monospaced block and copied with `wl-copy` through
  `promoteCopyArgv`, which returns `null` for an invalid name or empty image.
  `copyArgv` is not reused: its name guard rejects the text and its
  `--trim-newline` would eat the final newline.
- **It writes nothing** and has no nixarchy dependency.
- **The dotted-name limitation is accepted** (owner, 2026-09-19): distrobox
  allows `.` in a name, which makes an invalid Nix attribute path. The CLI has
  the same flaw and the output must match it, so the message area names it.

## How the fixture is produced and refreshed

The plugin repo can't build nixarchy in CI, and the spec requires a byte-exact
comparison. `promote_box` (`pkgs/box.nix:180-210` on nixarchy `main`) calls
both `distrobox` and `podman` **by bare name**, so the real CLI runs with two
stubs and no container:

```sh
d=$(mktemp -d)
printf '#!/bin/sh\nexit 0\n' > "$d/distrobox"
printf '#!/bin/sh\necho docker.io/library/ubuntu:24.04\n' > "$d/podman"
chmod +x "$d/distrobox" "$d/podman"
PATH="$d:$PATH" nix run github:olafkfreund/nixarchy/<commit>#nixarchy-box -- promote demo \
  > tests/model/fixtures/promote.txt
```

The fixture's first line is a comment naming that `<commit>` and the date, and
the command above goes in the PR body so anyone can reproduce it. Refresh it
the same way when nixarchy's wording changes; nixarchy#801 retires the CLI, and
from then on this panel is the source of truth, which is recorded on #801.

The fixture is data, not a generated file the build depends on: the test reads
it, nothing regenerates it automatically.

## Steps

1. `tests/model/fixtures/promote.txt`: create it with the command above, from
   a named nixarchy commit on `main`.
   → Verify by eye against `nixarchy box promote demo` run the same way, and by
   checking the file ends with `};` and a newline (`tail -c 4 | xxd`).
2. `tests/model/commands.test.js`: add the four cases from the spec, reading
   the fixture: `promoteSnippet` equals it byte for byte; `promoteImageArgv`
   for podman and for docker; `promoteCopyArgv` returns `null` for an empty
   image and for an invalid name; the shortcut list has `p` in the Box group
   and no group binds a key twice.
   → Verify by running **before** step 3: `node tests/run.js` must fail on the
   missing functions and the missing `p`. Capture that for the PR (§1).
3. `Model.js`: add `promoteSnippet`, `promoteImageArgv` and `promoteCopyArgv`,
   and the `p` entry in `SHORTCUTS` (line 31), which the shortcut sheet renders
   from, so `ShortcutSheet.qml` needs no edit.
   → Verify with `node tests/run.js`: all four cases pass, and the rest stay
   green.
4. `DistroboxState.qml`: a `promote(box)` action that runs
   `promoteImageArgv(Model.engineFor(settings.containerManager), box.name)`,
   and on success stores the snippet and runs `promoteCopyArgv`; on an empty
   result stores the error text instead. It never touches the poll timer.
   → Verify with `nix flake check` (QML syntax, manifest and the no-symlink,
   no-pacman, no-hex-colour assertions).
5. `BoxList.qml` and `DistroboxView.qml`: bind `p` on the selected row, add the
   row button beside the existing ones with an icon from the same set, and show
   the snippet in a selectable monospaced block followed by the "Copied. Paste
   into this host's nixarchy configuration; a rebuild then owns the box." line,
   or the error when there is one.
   → Verify with `nix flake check`, then by hand in step 6.

   **Deviation, as built:** `BoxList.qml` needed no edit. It renders its row
   buttons from `Model.actionsFor`, so the button is an entry there —
   `Glyph.copy`, the one glyph in the set nothing else used, because what the
   button does is copy. It is enabled while something mutates, unlike every
   other action: it reads the image and copies text, so the mutation lock has
   nothing to say about it. That moved a Model.js edit into step 5, and
   `tests/model/commands.test.js` gained two cases for it: the existing
   `actionsFor` list assertion now expects `promote`, and a new case asserts
   every row action's tooltip names a key the Box shortcuts actually bind. The
   snippet block uses `font.family: "monospace"` because the shell's `Style`
   has no mono token.
6. **By hand on a live session** (the only check of the QML wiring): create a
   demo box, press `p`, paste, and `diff` it against
   `nixarchy box promote <name>`. The diff must be empty. Put it in the PR.
7. `README.md` and `docs/usage.md`: the `p` key, what it copies, that it writes
   nothing, and the dotted-name limitation.
   → Verify by reading.
8. Open the PR: `Closes #14`, links to the intent, spec and plan, the red
   output from step 2, the empty diff from step 6, and the fixture command.

## Rollback

Revert the commits. Everything added is new: three pure functions, one
shortcut, one action and its UI. Nothing existing changes behaviour, nothing is
written to disk, and the fixture is only read by a test. A revert leaves boxes,
settings and the menu untouched.
