# Intent: a box can be promoted to a declared machine from the panel

## Problem

nixarchy made this panel the default Boxes UI (olafkfreund/nixarchy#803) and wants
to retire its own `nixarchy box` CLI (olafkfreund/nixarchy#801). Checked against
nixarchy's `main`, one of the three things #801 asks for is genuinely missing here:

- **`promote` is missing.** `promote_box` in nixarchy's `pkgs/box.nix:180-210`
  reads the box's image with
  `podman inspect --type container --format '{{.Config.Image}}'` and prints a
  snippet the user pastes into their flake:

  ```nix
  programs.nixarchy.services.boxes.machines.<name> = {
    image = "<image>";
    # Add whatever else this box needs -- additional_packages, init_hooks,
    # exported_apps -- see distrobox-assemble's manual. …
  };
  ```

  It is the documented way to keep a box made by hand
  (nixarchy `docs/manual/boxes.md:132`). The panel has no equivalent, so a user
  who lives in the panel has to drop to a shell for the one step that makes a
  box survive a rebuild.
- **`--check` is already covered.** The Boxes menu row is gated on
  `nixarchy-plugin --enabled nixarchy.distrobox` (nixarchy
  `modules/apps.nix:683-691`), not on `nixarchy box --check`.
- **`list` has no consumer.** Nothing in nixarchy outside the CLI's own help
  calls `nixarchy box list`.

So this task is only about promote.

## Proposed outcome

- A key on a box row in both surfaces produces the same snippet nixarchy's CLI
  prints, for the box under the cursor, and puts it on the clipboard.
- The user sees that it was copied, and sees the snippet itself before pasting —
  it names their box and goes into their flake, so it should not be an invisible
  clipboard write.
- Nothing is written to the user's flake or to any file. The panel copies; the
  user pastes. Same contract as the CLI, which only prints.
- Once this lands, nixarchy can retire `nixarchy box` (#801) without losing a
  documented workflow.

## Affected users and systems

- This repository: `Model.js` (the snippet and its argv, with Node tests),
  `DistroboxView.qml` and the drawing pieces, `ShortcutSheet.qml`,
  `docs/usage.md` and the README.
- nixarchy: #801 can close once this ships and the flake input is bumped.
- Everyone using the plugin (p620 and razer), on the next input bump.
- `wl-copy`, already a documented requirement (README:95, `docs/usage.md:27`)
  and already used for copying a box name (`Model.js:577`).

## Constraints

- AGENTS.md: the snippet and every argv are built in `Model.js`, return `null`
  on invalid input, and are covered by a Node test. QML only draws and wires.
- Argv arrays only. The snippet is user-influenced text (it embeds a box name
  and an image reference), so it is passed as one argv element to `wl-copy`,
  never through a shell.
- Read-only. Promote must not lock the singleton: it is not a mutation, and it
  must work while a create or upgrade is streaming.
- The snippet must stay byte-identical in shape to what nixarchy's CLI prints,
  so the two agree while both exist.
- A user-visible change, so `docs/usage.md` and the README move in the same PR.

## Open questions

1. **Where does the image come from?** `Model.js:239` already parses `Image`
   from the engine's `ps` output for every row, so the snippet costs no extra
   process. nixarchy's CLI instead runs `podman inspect` for `.Config.Image`.
   They normally agree, but can diverge (an image retagged, or pulled by digest,
   after the box was created). Default: use the row's `ps` image and spend no
   process. Alternative: one `inspect` per promote, for exactness.
2. **How is the snippet shown?** Default: reuse the existing log view to show it
   with a "copied" line, since it already exists and scrolls. Alternative: a
   toast-style line under the list, which is less code but truncates a
   multi-line snippet.
3. **Which key?** `c` already copies the box name. Default: `p` for promote.
4. **Docker boxes.** This panel supports docker via
   `DBX_CONTAINER_MANAGER`; nixarchy's `services.boxes` is podman-only.
   Default: still offer promote, since the snippet is only text the user may or
   may not paste. Alternative: hide the key for docker boxes.
5. **Does the comment block belong in the copied text?** The CLI includes the
   four-line "add whatever else this box needs" comment. Default: keep it, so
   both tools produce the same thing.
