# Intent: a box can be promoted to a declared machine from the panel

Closes #14.

## Problem

nixarchy made this panel its default Boxes UI (olafkfreund/nixarchy#803), and
wants to retire its own `nixarchy box` CLI (olafkfreund/nixarchy#801). One
thing the CLI does has no home in the panel: **promote**.

`nixarchy box promote <name>` turns a box you made by hand into something you
declare. It reads the box's image with
`podman inspect --type container --format '{{.Config.Image}}'`, then prints a
`programs.nixarchy.services.boxes.machines.<name> = { image = "…"; };` snippet
for the user to paste into their configuration (nixarchy `pkgs/box.nix:180-205`;
documented at `docs/manual/boxes.md:132`). From then on the box is declared,
and rebuilt by `distrobox assemble`, instead of living only in podman's state.

The other two things #801 lists are not needed here:
- `--check` is already covered: the Boxes menu row is gated on
  `nixarchy-plugin --enabled nixarchy.distrobox` (nixarchy
  `modules/apps.nix:683-691`).
- `list` has no consumer outside the CLI's own help.

## Proposed outcome

- A key on a box row (and its action button) **promotes** it: the panel shows
  the same `machines.<name>` snippet `nixarchy box promote` prints, image
  included, and copies it to the clipboard.
- It says where to paste it (the host's nixarchy configuration) and that a
  rebuild then owns the box.
- Nothing is written anywhere. The user pastes the snippet; the panel never
  edits a flake or a config file.
- When the image cannot be read (the engine is down, the box is gone), it says
  so rather than producing a snippet with an empty image.

## Affected users and systems

Anyone using this panel on nixarchy, where it is the default Boxes UI. It works
the same without nixarchy: the snippet is nixarchy's option, but copying text
is harmless anywhere. It affects `Model.js`, the row actions, the shortcut
sheet and the docs.

## Constraints

- **Read-only.** Never write to the user's flake, `~/.config/nixarchy/*` or any
  file. Copy and show only, the same as the CLI.
- **Use the engine the panel already talks to** (`containerManager`, podman by
  default), not a second podman on PATH. The CLI's header explains why.
- **Same snippet as the CLI,** so the manual's promote section stays true when
  nixarchy retires the CLI.
- No new daemon, and no dependency beyond `wl-copy`, which the panel already
  uses.
- Node tests for the snippet builder, proven failing first, as the repo's other
  Model.js tests are.

## Open questions

1. **Key.** `p` is free in the shortcut sheet today. Use it?
2. **Snippet contents.** The CLI emits only `image` plus a comment pointing at
   `additional_packages`, `init_hooks` and `exported_apps`. Should the panel also
   fill in what it can read (for example `init` from the container's labels), or
   stay identical to the CLI? The default is identical.

**Decided on approval (owner, 2026-09-19):** the promote key is p, and the snippet matches nixarchy box promote exactly.
